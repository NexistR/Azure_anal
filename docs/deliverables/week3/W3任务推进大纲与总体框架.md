## 本周目标

把 W2 已发现的问题变成可反复执行、会自动检查错误的数据清洗流程。简单来说：原始 CSV 作为只读原材料，脚本按统一规则处理，输出干净且语义明确的数据，再留下“改了什么、为什么改、检查是否通过”的证据。

已读取主项目 13 份项目自有 README，以及 `week2_sub/W2完成报告_2026-09-09.md`、`项目结构与构成说明.md`。实施还以 W2→W3 十条清洗建议、W1 数据合同、八周路线图及原始 brief 第三周要求为依据。第三方环境和工具包内的 README 不作为项目需求。读取文件及指纹将登记到主项目 `reports/tables/w3_source_reading_register.csv`。

## 任务推进

1. **D1：冻结规则与基线。** 核验 W1 原始文件 SHA-256，冻结 Telco 主表的字段、主键、标签、类别和范围。把 C01–C10 逐项对应到代码及验收。明确 11 个累计费用空白与零年限客户的关系。
2. **D2：实现清洗。** 空白金额转成数值缺失并标记，合法金额转为数值；清理类别前后空白并验证白名单；保留无互联网/无电话的结构性类别；检查主键、标签、数值范围和跨列逻辑；仅登记费用差异与统计离群值，不擅自删行或缩尾。
3. **D3：预处理和设计。** 提供可 fit/transform 的标准化、编码接口。通过固定种子的随机分层示例切分验证训练内插补/缩放与维度稳定；生成没有 NA/inf 的示例数值矩阵。写《特征工程设计文档》v1，设计不少于 10 个真实时间序列特征及其所需数据、窗口和泄漏约束。
4. **D4：验证并交付。** 运行真实数据与负向测试；从非项目目录、隔离干净环境和新 Notebook 内核重跑；检查数据/汇总表指纹稳定及原始文件不变；更新 README 和运行说明；最后填写完成报告和验收清单。

## 必须如实说明的限制

- 原始“处理后无缺失和异常”的字面要求不能靠编造累计费用满足。清洗主表保留 11 个未知值并标记；训练内预处理的数值矩阵可以无缺失。已知非法值/逻辑冲突为零只表示所列规则通过，不证明所有业务异常都不存在。
- 原始 brief 的“设计至少 10 个时间序列特征”按设计交付；Telco 没有快照日期、使用日志、账单或续约历史，因此真实时间特征计算仍缺数据。不得用年限的十种变形充作十个时间序列特征。
- 不合并无共同客户键的工单与 SaaS 表，不新增虚构地区、行业或日期。W2 的这些数据缺口继续登记。
- 本周的随机分层切分只验证预处理接口，不代替 W5 模型评估；不提前训练模型、承诺 CLV/ROI 或未来流失概率。W4 再完成正式候选特征与筛选。
