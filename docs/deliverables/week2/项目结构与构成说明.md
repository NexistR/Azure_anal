# 项目结构与构成：零基础说明

你可以把整个项目想成一间分析工作室：`data` 是原材料，`src` 是工具，`notebooks` 是实验记录本，`scripts` 是自动化按钮，`reports` 是最终报告和证据，`docs` 是使用说明。

## 两个目录现在分别放什么

### `week2_sub/`

这里现在只保留 W2 完成报告和本目录的两份零基础说明。W2 的实际代码、图表、表格和 Notebook 已经全部整合到 `azure-churn-clv/`，所以不要再从 `week2_sub` 运行旧路径。

### `azure-churn-clv/`

这是主项目根目录。W1 的基础资料和 W2 的实际交付物都在这里，后续 W3 到 W8 也应继续沿用这个根目录。

## 主目录逐个解释

### `data/`：原始材料和处理结果

- `data/raw/`：下载的原始数据，只读保存。Telco CSV 位于 `data/raw/telco_customer_churn/`。
- `data/processed/`：未来存放清洗后的数据和特征。当前 W2 没有输出客户级清洗数据。
- 目录里的 README 说明数据来源、读写约定和不可提交的文件。

### `src/`：真正干活的 Python 代码

- `src/w2_analysis.py`：W2 的核心代码。负责读数据、检查数据、创建临时字段、计算流失率、统计检验、画图和写 CSV。
- `src/data/`：数据读取、质量检查和清洗代码的预留位置。
- `src/features/`：未来的特征工程代码。
- `src/models/`：未来的模型训练、评估和预测代码。
- `src/segmentation/`：未来的客户分层、分群和风险价值矩阵代码。
- `__init__.py`：告诉 Python 这是一个可导入的代码包。

### `scripts/`：可以直接运行的按钮

- `run_week2.py`：一键生成/执行 W2 Notebook，导出 HTML，验证图表和表格，并写入验收 JSON 与文件清单。
- `build_w2_powerbi.py`：把同一份 W2 分析数据做成 Power BI 原生项目，包含数据快照、计算公式、四页图表和筛选器。
- `build_w2_web_dashboard.py`：把同一份数据和交互图表打包成一个离线网页。
- `setup_week2_environment.ps1`：准备 W2 使用的 Python 3.12 环境和 `azure-w2` 内核。
- `setup_environment.ps1`：项目通用环境安装入口，面向整个八周项目。
- `launch_kernel.py`：启动项目专用 Jupyter 内核，并设置绘图兼容处理。
- `register_kernel.py`：把 `azure-w2` 内核注册到项目虚拟环境中。
- `verify_environment.py`：检查 Python 科学计算库、绘图和 Notebook 内核是否能正常工作。
- `recover_cached_python.py`：在原有 Python 路径损坏时，尝试从本机缓存恢复运行时。
- `profile_data.py`：W1 数据质量检查脚本。

### `notebooks/`：带过程的实验记录

- `02_eda.ipynb`：W2 的完整探索分析，包含代码、表格、图和文字解释。
- `02_eda.html`：Notebook 的静态网页版本，适合只读查看。
- `README.md`：说明 Notebook 的编号和职责。

Notebook 更像“操作记录本”，不应该复制一份核心业务逻辑。核心计算放在 `src`，这样脚本、Notebook 和将来的模型都能复用。

### `reports/`：报告和证据

这里同时有 W1 和 W2 文件。W2 重点文件包括：

- `w2_eda_summary.md`：用文字总结主要发现。
- `w2_eda_report.html`：把总结、方法和 20 张内嵌图放在一个网页里。
- `w2_methods_and_decisions.md`：记录口径、统计方法和为什么这样处理。
- `w2_to_w3_cleaning_recommendations.md`：交给 W3 的清洗任务和验收标准。
- `w2_analysis_metadata.json`：数据哈希、参数和依赖版本等元数据。
- `w2_verification.json`：W2 是否通过重跑和完整性检查。
- `w2_artifact_manifest.csv`：交付文件的大小和 SHA-256 指纹。
- `figures/w2_eda/`：20 张 PNG 图表。
- `tables/w2_*.csv`：机器可读的统计汇总表。

同一目录下的 `data_contract_v1.md`、`data_quality_report_v1.md`、`hypothesis_matrix_v1.md` 等是 W1 基线，它们是 W2 分析的输入和约束。

### `docs/`：给人看的项目说明

- `docs/project/`：项目背景、目标和原始 brief。
- `docs/planning/`：八周计划、路线图和任务框架。
- `docs/operations/`：环境安装、运行入口、当前进度和交接说明。
- `docs/archive/`：历史版本，只用于追溯。

### `references/`：参考原文

`references/project_brief_extracted.txt` 是从原始 PDF 提取的文字，方便搜索和核对。它不是分析结果，而是项目需求的参考来源。

### `configs/`：配置

这里放路径、随机种子和运行参数等配置说明。配置集中管理后，换机器或换数据版本时不需要到处修改代码。

### `models/`：模型产物

未来训练出的模型文件放在这里。当前 W2 没有训练模型，所以这里仍是预留位置。

### `dashboard/`：展示层

现在已经有两种交互入口：

- [powerbi/W2_Churn.pbip](../../../dashboard/powerbi/W2_Churn.pbip)：用 Power BI Desktop 打开。`.pbip` 像入口钥匙，旁边的 `.Report` 文件夹保存页面布局，`.SemanticModel` 文件夹保存数据快照和公式；三个部分要一起保留。首次提示无数据时点“刷新”。
- [w2_interactive.html](../../../dashboard/w2_interactive.html)：用浏览器打开，15 个图表可随筛选更新，不需要 Power BI。

Power BI 报告有 4 页、21 个分析视觉对象，支持合同、网络、付款、年限、月费五个真实字段。地区、行业和真实 Azure 订阅类型在原始数据中缺失，因此这项原始要求仍待补数据。[详细打开说明](../../operations/W2_run_and_delivery.md)解释了操作和数据更新方法。

### `tests/`：自动检查

这里放数据质量规则和代码测试。测试的目的，是让后续修改不会悄悄破坏数据合同或输出格式。

### `tools/`：辅助工具

这里放环境检查、冒烟测试和 Markdown/PDF 渲染等工具。它们帮助确认项目能启动、能导入依赖、能生成文档。

### 根目录的依赖文件

- `requirements.txt`：最基础的依赖入口。
- `requirements-core.txt`：核心 Python 依赖。
- `requirements-advanced.txt`：高级模型依赖。
- `requirements-optional.txt`：可选的 Spark 等依赖。
- `requirements-all.txt`：组合安装入口。
- `requirements_w2.txt`：W2 实际验证过的 Python 3.12 依赖版本。

### `.venv`、`.runtime`、`.cache`

这些是本机运行环境和缓存，不是业务代码，也不是报告。它们可能很大、和电脑绑定，而且会随运行变化，所以被 `.gitignore` 排除。删除后可以按照环境说明重新创建。

## 一次 W2 运行时文件如何流动

```text
data/raw/*.csv
        ↓
src/w2_analysis.py 读取、检查、计算
        ↓
scripts/run_week2.py 编排 Notebook 和验证
        ↓
notebooks/02_eda.ipynb + 02_eda.html
reports/tables/w2_*.csv
reports/figures/w2_eda/*.png
reports/w2_*.md / *.json
```

最重要的原则是：原始数据放在 `data/raw`，可复用逻辑放在 `src`，执行入口放在 `scripts`，展示过程放在 `notebooks`，最终证据放在 `reports`。这样别人才能知道每个文件为什么存在、应该从哪里运行，以及结果能不能追溯。
