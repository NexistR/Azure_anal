# W2 到底做了什么：零基础也能看懂的说明

这份文档把 W2 当成一次“先把数据看明白，再决定下一步做什么”的检查。W2 不是训练上线模型，也不是证明某个原因一定会导致客户流失。它做的是探索性数据分析（EDA）：把已有客户资料分组、计算流失比例、画图，然后把能观察到的现象和不能确定的事情写清楚。

## 先认识这份数据

数据是公开的 Telco Customer Churn 数据集，共 7,043 行、21 列。可以把每一行理解为一个客户在某个时点的资料快照。重要字段有：

- `Churn`：客户是否流失，`Yes` 表示流失，`No` 表示没有流失。
- `Contract`：合同类型（月付、一年、两年）。
- `tenure`：客户已经使用了多少个月。
- `MonthlyCharges`：每月费用，是本项目用来表示“费用/价值”的代理指标。
- `InternetService`：DSL、Fiber optic 或 No。
- 六个增值服务字段：网络安全、网络备份、设备保护、技术支持、电视和电影服务。
- `PaymentMethod`：客户使用的付款方式。

数据里 `customerID` 是客户编号，`TotalCharges` 是累计费用。W2 保留客户编号用于检查重复，却不把编号当作分析特征；`TotalCharges` 有 11 个空白字符串，W2 只登记这个问题，没有偷偷填数或把它混进分析。

## W2 按顺序做了什么

### 1. 先检查数据有没有被换掉

程序先读取 W1 的数据清单，计算原始 CSV 的 SHA-256 哈希值。哈希可以理解为文件的“指纹”：只要文件内容改了一点，指纹通常就会改变。指纹不一致时程序会直接停止，避免拿错数据继续分析。

接着检查行列数、客户编号是否为空或重复、`Churn` 是否只有 Yes/No、月份和费用是否在合理范围内，以及六个服务字段是否使用预期的类别。

### 2. 建立可计算的临时字段

原始字段尽量保留不动，程序另外创建一些临时字段：

- 把 `Churn=Yes/No` 转成 `churn=1/0`，方便计算比例。
- 把使用月数切成 `[0,6)`、`[6,12)`、`[12,24)`、`[24,48)`、`[48,73)` 五组。左边包含、右边不包含，例如 6 个月属于第二组。
- 计算每个客户使用了几个增值服务。
- 按月费四分位数分成 Q1 到 Q4。
- 根据是否有互联网、是否高月费、服务数量多少、是否手动付款等规则建立分析标签。
- 把“月付且使用少于 6 个月”标成一个风险规则示例。它只是筛选规则，不是模型预测概率。

这些字段只用于本次统计和画图，不会被当成已经训练好的客户特征文件。

### 3. 计算每组的流失率

对每一个分组，程序统计三件事：这一组有多少人（`n`）、其中多少人流失（`churned`）、流失人数除以总人数是多少（`churn_rate`）。

同时计算 Wilson 95% 区间。可以把它理解为“这个比例大概可能落在哪个范围”，比只报一个百分比更诚实，尤其是小样本组。样本少于 30 人的组会被标记为 `small_group`，提醒阅读者不要过度解读。

### 4. 检验 W1 提出的假设

W1 提出了 H1 到 H10。W2 优先处理数据确实支持的 H1、H2、H4、H10，并补充 H5、H6、H9：

- H1：合同类型和流失是否有关。
- H2：使用年限和流失是否有关。
- H4：增值服务数量/具体服务和流失是否有关。
- H5：费用与服务数量组合是否有关。
- H6：付款方式和流失是否有关。
- H9：人口统计字段和流失是否有关。
- H10：月费分组和流失是否有关。

分类字段通常使用卡方检验；期望频数太小时改用 Fisher 精确检验。数值或有顺序的字段使用 Spearman 秩相关。多次检验会做 Bonferroni 校正，降低“碰巧显著”的风险。统计显著只说明数据中存在关联，不能证明因果关系。

### 5. 输出表格和图表

`src/w2_analysis.py` 负责读取数据、计算统计量、保存 CSV 和生成 PNG；`scripts/run_week2.py` 负责组织执行顺序、运行 Notebook、检查结果、导出 HTML 报告和生成哈希清单。

W2 最终生成 20 张 300 dpi PNG，覆盖分布图、分组流失率图、交叉热力图和服务组合图；同时生成 28 张左右的 CSV 汇总表。图表映射表会记录每张图对应的假设、结论、下一步行动、证据表和限制条件。

### 6. 做一次可重复性检查

使用两个全新的 Jupyter 内核各运行一遍 Notebook，再比较所有 CSV 和 PNG 的 SHA-256。如果两次结果不同，程序报错。这样可以发现随机数、路径或环境造成的隐性差异。项目固定随机种子为 42。

## 2026-09-13 补充：把图变成可以点击的仪表板

原来的 PNG 和报告像一张“已经印好的照片”：可以看，却不能自己换人群。现在新增了一个 Power BI 报告和一个浏览器交互网页。比如在合同框里选 `Month-to-month`，页面就只计算月付客户，人数从 7,043 变为 3,875，流失人数变为 1,655，观察流失率变为 42.71%。同时选付款方式，相当于继续缩小人群。

**Power BI 入口**是 [W2_Churn.pbip](../../../dashboard/powerbi/W2_Churn.pbip)。用 Power BI Desktop 打开，如果说“没有数据”就点“立即刷新”。底部四个页面分别看总体与合同/年限、增值服务、付款与人口特征、组合模式。没有 Power BI 时，可以双击 [w2_interactive.html](../../../dashboard/w2_interactive.html)，用浏览器操作 15 个图表。

它的实现可以分成三步：

1. Python 用原来的 `load_data()` 读取并检查同一份 CSV，生成分组字段，保证和 Notebook 口径一致。
2. `build_w2_powerbi.py` 把需要的字段放入 Power BI 数据模型，写入计算公式。公式随筛选重新计算人数和“流失人数 ÷ 总人数”。它保存的是一份内嵌快照，不需要连接云数据库。
3. 程序生成四页图表和筛选器。`build_w2_web_dashboard.py` 则把图表程序和数据放进一个 HTML 文件，浏览器直接计算筛选结果。

最容易踩的三个新坑：

- **刷新不等于重新运行 Python。** 数据变更后，要先重跑构建脚本，再打开 Power BI 刷新；重建会覆盖生成布局，手工美化请先另存副本。
- **筛选后必须看人数。** 例如只剩 3 人时，流失率 66.7% 也只有 2 个人，不能当作稳定规律。没有任何客户时不应把空白流失率理解为“零风险”。
- **不能为了凑筛选框而编造地区和行业。** 公开 Telco CSV 没有这些字段，也没有真实 Azure 订阅类型。当前合同字段只是代理；缺少真实映射表，这部分原始要求就还没有完成。

## 分析结果的边界

W2 观察到：月付客户和短年限客户的观察流失率较高；一些付款方式、服务组合和月费分组也存在差异。但这些都是当前数据快照中的关联。数据没有客户事件日期、连续账单、地区、行业、真实成本和利润，所以不能据此宣称“某个动作一定能减少流失”，也不能把 `MonthlyCharges` 叫作正式 CLV，更不能把结果说成 Azure 真实客户结果。

H3、H7、H8 没有被强行判定为通过：分别因为缺少可靠时间序列、工单客户 ID/时间映射和续约历史。把“无法验证”写出来，是分析质量的一部分。

## 怎么运行

在 `azure-churn-clv` 根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup_week2_environment.ps1
& .\.venv\Scripts\python.exe .\scripts\run_week2.py --verify-reproducibility
```

主要阅读入口是：

- `notebooks/02_eda.ipynb`：带代码和输出的 Notebook。
- `notebooks/02_eda.html`：可以直接用浏览器打开的版本。
- `reports/w2_eda_summary.md`：发现总结。
- `reports/w2_eda_report.html`：包含图表的完整报告。
- `reports/w2_to_w3_cleaning_recommendations.md`：给 W3 的清洗建议。
- `reports/w2_verification.json`：机器可读的验收记录。

## 最容易踩的坑

1. **不要把相对路径改成自己的硬编码绝对路径。** 代码会根据项目位置寻找数据，换电脑时只需要在项目根目录运行。
2. **不要把 `TotalCharges` 的空白直接当成 0。** 空白代表缺失，必须先确认业务含义。
3. **不要把 No internet service 当成普通缺失值。** 对没有互联网的客户，六个互联网增值服务本来就不适用。
4. **不要把横截面流失率当成未来预测。** 这里没有时间顺序，不能说“未来六个月会流失多少人”。
5. **不要把小样本组的高比例当成稳定规律。** 先看 `n` 和置信区间，必要时标记为探索结果。
6. **不要把 p 值当成业务影响大小。** 还要看比例差、效应量、样本量和业务可执行性。
7. **不要直接在 Notebook 里复制一套新逻辑。** 可复用计算应放在 `src/w2_analysis.py`，Notebook 只负责编排和展示。
8. **不要把运行环境目录当成项目交付物。** `.venv`、`.runtime`、`.cache` 是本机状态，已被 `.gitignore` 排除。
