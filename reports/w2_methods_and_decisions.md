# W2 方法与决策记录

日期：2026-09-13。W2 在 `azure-churn-clv/` 中完成，输入为 W1 冻结的 Telco 客户数据（7043 行、21 列）。

## 数据口径

- 原始 CSV 只读使用，先按 W1 SHA-256 清单校验；分析期间不得修改原始文件。
- 流失标签为 `Churn == Yes`。`TotalCharges` 的空白只做质量记录，不强行转数值或填补。
- 六项增值服务为 OnlineSecurity、OnlineBackup、DeviceProtection、TechSupport、StreamingTV、StreamingMovies。
- `tenure` 使用左闭右开区间 `[0,6)`、`[6,12)`、`[12,24)`、`[24,48)`、`[48,73)`。
- 高月费定义为 `MonthlyCharges >= 70.35`（全样本中位数）；低服务定义为六项服务数量 0–2 项。

## 分析与统计

Notebook 负责编排、展示和解释，核心计算集中在 `src/w2_analysis.py`。脚本生成 20 张 300 DPI 图、W2 汇总表和假设结果表。比例使用 Wilson 95% 区间；双侧检验按服务、人口等检验族分别进行 Bonferroni 校正，避免多重比较夸大显著性。

## 假设处理

H1（合同）、H2（客户年限）得到数据支持；H4（互联网客户的增值服务数量）、H5（高月费客户中的低服务）、H6（支付方式）、H9（人口细分）和 H10（月费分位）只在记录的比较范围内部分支持。H3（使用量时间序列）、H7（客户映射/生命周期）和 H8（自动续费历史）因数据缺少事件时间、客户键或续费字段，标记为不可验证。

## 重要限制

这些结果是横截面观察，不能解释因果关系，也不是未来流失概率、CLV、ROI 或资源分配模型。服务数量与流失的关联不能直接解读为加购效果；支付方式也不等于支付失败或自动续费。小样本分组应在 W3/W4 补充数据后复核。

## 2026-09-13 Power BI 补充交付决定

原始项目介绍把本地 Power BI 交互仪表板列为 W2 必須交付。本轮按用户指令补充 `.pbip`、PBIR 页面和语义模型；八周裁剪保留 W2 本地展示，不再据旧六类清单将它排除。离线 HTML 是另外的浏览器入口，不能作为原生 Power BI 要求的替代证明。

Power BI 使用同一 `load_data()` 的分析快照，移除客户编号与未清洗的累计费用。模型字段名不区分大小写，因此只保留原始 `Churn`，不同时导入 Python 的临时 `churn` 列；流失人数由 DAX 的 `Churn="Yes"` 计算。观察流失率随筛选重新计算分子与分母，空人群返回空白率，人数为 0。

六项服务的图表、提示中的人数/流失人数，以及服务页的平均月费都只在互联网客户内计算；高月费阈值固定为原始快照中位数 70.35，筛选之后不重新定义阈值。客户年限分组通过隐藏的顺序列按月份先后排列，避免字符串排序把 `[6,12)` 放到最后。图表的 H1 等编号关联到统计报告；动态筛选后的图表比例不等于重新运行假设检验，p 值和置信区间请查看对应的固定分析表及其人群范围。

当前原始表没有真实地区、行业、订阅类型。报告使用合同、网络、付款、年限和月费五个字段筛选，合同只作订阅代理，原始三个真实维度的验收仍未满足。接入额外维度时，构建脚本要求真实客户键一一匹配、全覆盖且无空值；不以模拟字段或无共同客户键的其他数据集凑齐要求。
