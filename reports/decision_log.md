### D001 - 项目范围收敛为 W1-W8

**日期**：2026-09-02  
**决策者**：项目团队  
**决策内容**：项目执行和验收范围明确为 W1-W8，原12周计划中的 W9-W12（正式 CLV、留存策略/实验、ROI 组合、综合发布）不属于本项目范围。

**影响**：

- W8 使用价值代理，不产出正式 CLV 模型

**状态**：✅ 已确认

### D002 - Telco 数据定位为代理/教学数据

**日期**：2026-09-03  
**决策者**：项目团队  
**决策内容**：明确 Telco Customer Churn 数据集是公开电信代理/教学数据，不是 Microsoft Azure 内部客户数据。  
**理由**：
- 数据来源为 Kaggle 公开数据集
- 字段为电信行业通用字段，非 Azure 云服务特征
- 避免误导和过度承诺

**影响**：
- 所有报告、字典和结论必须标注"代理数据"
- 业务假设基于一般云服务/订阅逻辑，字段映射基于 Telco 实际字段
- 结果外推需明确说明限制

**状态**：✅ 已确认

### D003 - 每周工作量基线

**日期**：2026-09-03  
**决策者**：项目团队  
**决策内容**：采用 15-18 小时/周的工作量基线，而非历史 PDF 中的 25-30 小时/周。  
**理由**：
- 更可持续的节奏
- 符合交接文档中的执行基线
- 保持 DoD 和数据治理红线不变

**影响**：
- 每周任务范围需匹配可用工时
- 优先级排序更加重要
- 工时变化不降低质量标准

**状态**：✅ 已确认

### D004 - 数据集分析策略

**日期**：2026-09-03  
**决策者**：项目团队  
**决策内容**：
- **Telco Customer Churn**：主分析数据集，完整执行 W1-W8 流程
- **Customer Support Tickets**：待验证客户 ID 关联后再决定是否整合
- **SaaS Churn Rate**：行业参考数据（5行汇总表），不做客户级合并

**理由**：
- Telco 数据规模和字段最完整
- 工单数据与 Telco 无已验证的统一客户 ID 和时间口径
- SaaS 数据是行业汇总，非客户明细

**影响**：
- W1 质量审计重点关注 Telco 数据
- 工单数据关联作为 W2+ 可选进阶项
- 假设验证优先使用 Telco 已有字段

**状态**：✅ 已确认
