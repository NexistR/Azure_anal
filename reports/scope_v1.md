# 项目范围说明 v1

> 创建日期：2026-09-03  
> 文档状态：v1 - 启动基线  
> 复核状态：待G0验收

## 一句话目标

基于公开 Telco 代理数据建立可信的数据与业务起点，为后续流失预测和价值决策提供可复核依据。

## 项目四问

本项目在八周内回答以下问题：

| 业务问题 | 分析目标 | 交付物 |
|---------|---------|--------|
| 1. 谁可能流失 | 校准的客户级风险概率和风险等级 | W5-W7：预测模型、风险评分、概率校准 |
| 2. 为什么可能流失 | 可验证的驱动因素和客户级原因码 | W2：EDA假设验证；W7：模型解释 |
| 3. 谁值得优先处理 | 风险×价值矩阵和客户分群 | W8：风险-价值四象限、客户分层 |
| 4. 怎样证明挽留有效 | （范围外接口）记录所需数据和限制 | W8：未来扩展说明，不在W1-W8实施 |

## 代理数据声明

**重要边界**：本项目使用的 Telco Customer Churn 数据集来自 Kaggle 公开数据，是**电信行业代理/教学数据**，**不是 Microsoft Azure 内部真实客户数据**。

所有分析结论、字段映射和业务假设均基于此公开代理数据；结果不能直接表述为 Azure 实测事实，需要明确标注数据来源和外推限制。

## 项目范围（W1-W8）

### 范围内

| 周次 | 核心交付 |
|------|---------|
| W1 | 业务理解、数据合同、字段字典、质量审计、路线图 |
| W2 | 问题导向EDA和假设验证 |
| W3 | 可复用数据清洗Pipeline |
| W4 | 特征工程和泄漏审查 |
| W5 | 基线模型、不平衡处理和完整指标 |
| W6 | 高级模型、调参与细分稳定性 |
| W7 | 模型解释、概率校准和风险评分 |
| W8 | 价值代理、客户分层/分群、风险-价值矩阵和项目收口 |

### 明确不在范围内（不实施、不验收）

- 正式 BG/NBD 或 Gamma-Gamma CLV 模型
- 留存策略执行
- A/B 测试、uplift 建模或因果效果估计
- 策略组合 ROI 优化
- 原12周计划中的 W9-W12 综合发布任务
- Azure 云端正式部署和在线发布

## MVP 与进阶边界

### MVP（最小可交付）

- 使用 Telco 主数据集完成完整的八周流程
- 基于现有字段的预测模型和解释
- 使用 `MonthlyCharges`、`TotalCharges` 等透明价值代理
- 随机分层切分的基线验证（Telco 缺时间字段）
- 本地开发环境和报告交付

### 进阶（数据/时间允许时）

- 整合 Customer Support Tickets 数据（需验证客户ID对应关系）
- 严格时间切分验证（需获取快照时间字段）
- 更精细的价值分层（需获取成本、毛利数据）
- Azure 云端资源和 Power BI 在线发布

## 本周非目标

第一周**不追求**以下内容：

- ❌ 立即训练模型和追求指标分数
- ❌ 完成最终的特征工程和数据清洗
- ❌ 确定最终的客户分群方案
- ❌ 产出可行动的业务建议
- ❌ Azure 云端登录和资源创建
- ❌ Git 首次提交和远程仓库连接

第一周**专注于**：

- ✅ 冻结业务和数据口径
- ✅ 建立可审计的数据起点
- ✅ 识别数据质量问题和风险
- ✅ 拆解后续7周的可执行路线图

## 已确认边界

### 数据边界

1. **主分析数据**：Telco Customer Churn (7,043行, 21列)
2. **辅助数据**：Customer Support Tickets (8,469行, 17列) - 需验证关联
3. **参考数据**：SaaS Churn Rate (5行, 4列) - 行业汇总，不做客户级合并

### 时间边界

- 项目周期：8周（W1-W8）
- 每周投入：15-18小时
- 第一周投入：约14-18小时（D1-D7，每天2-3小时）

### 技术边界

- 开发环境：Python 3.12 + Jupyter + VS Code
- 建模工具：Scikit-learn, XGBoost, LightGBM
- 解释工具：SHAP, LIME
- 可视化：Matplotlib, Seaborn, Power BI Desktop
- 版本控制：Git (本地)

### 资源边界

- 本地开发为主
- Azure 云端资源为可选进阶项
- 不依赖付费第三方服务

## 未决问题清单

以下问题将在 D2-D4 逐步确认：

1. [ ] Telco 数据的精确客户粒度（一行是否等于一个唯一客户）
2. [ ] `Churn` 标签的精确定义和观察窗口
3. [ ] 是否存在快照时间字段（影响时间切分可行性）
4. [ ] `MonthlyCharges` vs `TotalCharges` 的精确含义和价值代理选择
5. [ ] Customer Support Tickets 与 Telco 的客户ID关联可行性
6. [ ] 数据质量问题的严重程度和修复优先级

## 红线（不可违反）

- ❌ 不能将 Telco 公开数据写成 Azure 内部数据
- ❌ 不能无依据删除异常客户（先记录、分析、建议）
- ❌ 不能将相关性表述为因果性
- ❌ 不能把 brief 背景数字写成项目实测结果
- ❌ 不能为追求指标而泄漏未来信息或改标签
- ❌ 不能强行合并无共同ID/时间口径的数据集
- ❌ 不能把范围外任务（正式CLV、实验、ROI）列入待办
