# W3 数据清洗规则与处理边界

日期：2026-09-16。规则版本：`w3-telco-cleaning-v1.0.0`。本文件说明已经实现的清洗和预处理接口应如何使用、如何验收；本次运行的实测数量、测试结果和文件指纹以 W3 完成报告及运行生成的证据为准。

依据是 [W2→W3 清洗交接](w2_to_w3_cleaning_recommendations.md)、[数据合同](data_contract_v1.md)、[八周路线图](roadmap_8w_v1.md)及原始 brief。实际实现为 [clean.py](../src/data/clean.py)、[preprocess.py](../src/data/preprocess.py)，参数与类别字典在 [w3_cleaning.json](../configs/w3_cleaning.json)。

## 1. 清洗究竟在做什么

可以把一行数据看成一个客户的登记表。清洗先检查登记表是否缺页、客户编号是否重复、金额能不能读成数字、服务状态是否自相矛盾，然后统一书写方式。没有证据的金额仍记为“未知”，不会为了让表格好看就编一个金额。

这个流程有两层：

| 层次 | 内容 | 用途与限制 |
|---|---|---|
| 清洗主表 | 21 个原始字段，加 4 个可追溯字段，共 25 列 | 保存可信的字段语义；`TotalCharges` 可以保留明确缺失。适合核查和 W4 接续。 |
| 模型数值接口 | 从主表取 22 个允许字段，训练子集拟合后转为 49 列数值矩阵 | 演示插补、标准化和编码；输出须无 NA/无穷大。插补结果不能反写成已知历史账单，也不是 W4 最终特征集。 |

两个层次解决不同问题。“机器能接受一个有限数值”不意味着“已经知道客户真实累计付了多少钱”。

## 2. 输入合同和输出字段

输入为单一 Telco 客户快照。读取器使用字符串方式读 CSV，并关闭默认 NA 识别，以便区别真实空白和无法解析的非空文本。清洗器接受完整的 21 列原表，或自己产生的完整 25 列主表；少列、多列、重复列、只带部分衍生列、空表会报错，不静默丢弃新字段。

W2 冻结基线为 7,043 行、21 列，输入 SHA-256 为 `88be4b93fbe0cc83421af1c503794c97c342eca914c1576db7c276e61d61358a`。这是一批输入的验收基线，不是清洗器只能处理 7,043 行的限制。换数据应更新来源登记、哈希与验收基线，不能跳过来源确认。

原始 21 列依配置顺序保留。新增列如下：

| 新增列 | 公式 | 类型 | 能否进入 X |
|---|---|---|---|
| `churn_label` | `Churn` 为 Yes→1、No→0 | 整数 0/1 | 否，单独作为 y |
| `total_charges_missing` | `TotalCharges` 为缺失时记 1，否则 0 | 整数 0/1 | 是；保留原始金额未知的事实 |
| `tenure_zero` | `tenure == 0` 时记 1，否则 0 | 整数 0/1 | 是；表示静态年限边界 |
| `internet_applicable` | `InternetService != 'No'` 时记 1，否则 0 | 整数 0/1 | 是；区分互联网增值服务适用人群 |

`customerID` 只用于追踪，原 `Churn` 和 `churn_label` 都不得进入 X。`split_xy()` 严格要求完整的 25 列清洗表，返回互相独立的 X、y、客户编号副本。X 白名单是 3 个数值字段、16 个类别字段和 3 个非标签标记，共 22 列。

## 3. C01–C10 逐项规则

| 交接编号 | 实际处理规则 | 自动约束与应保留证据 |
|---|---|---|
| C01：累计金额空白和类型 | 所有字符串去首尾空白；将 `TotalCharges` 的空字符串或真实空值保留为 NA，其余转为 float64。解析时即使用了 `errors='coerce'`，紧接着也会检查非空值变 NA 的情况并报错。 | 空白数、原有空值数、非空解析失败数、转换前后 dtype；非空垃圾文本不能被当成正常缺失，更不能转为 0。 |
| C02：零年限客户 | 保留 `tenure=0` 客户与未知累计金额，分别生成 `tenure_zero`、`total_charges_missing`。主表不做总体中位数插补、不删客户。 | 当前 W2 基线是 11 个空白与 11 个零年限客户重合；运行前后需对账。新批次并不强制二者一定重合，出现不同组合时应登记复核。 |
| C03：服务不适用 | 六项互联网增值服务保留 `No internet service`，并生成 `internet_applicable`。不将不适用状态改成普通缺失。 | 逐列要求 `InternetService=No` 当且仅当该服务为 `No internet service`；核对各类频数和适用人群。 |
| C04：显式类别规则 | 只清除首尾空白；类别拼写与大小写必须符合配置，不做模糊匹配。InternetService 仅允许 DSL/Fiber optic/No。 | 未知类别明确失败；电话与多线服务同样要求 `PhoneService=No` 当且仅当 `MultipleLines=No phone service`。不在 W3 主表新增正式服务计数。 |
| C05：主键和标签 | 客户 ID 必须为非空字符串，去空白后唯一；标签只允许 No/Yes；保留原标签并显式映射。 | 行数、ID 集合、标签人数及逐客户标签对应关系前后对账。重复客户不擅自去重；未知/缺失标签失败；预处理白名单拒绝任何额外字段。 |
| C06：范围和异常 | 数值必须为有限实数；年限为非负整数，月费大于 0，累计费用非负或明确缺失。SeniorCitizen 只能为整数 0/1。 | 非法值失败；分布/IQR 诊断与业务非法值分开记录。不将 72 月、118.75 月费等当前样本最大值设为永久上限，不删行、缩尾或自动覆盖罕见值。 |
| C07：金额关系 | 比较 `TotalCharges` 与 `tenure × MonthlyCharges` 作为诊断；清洗函数不以乘积回填或覆盖累计金额。 | 报告差值分布、有效分母、缺失和零年限边界。历史月费、折扣未知，差值不直接计为脏数据。 |
| C08：时间限制 | 只清洗真实静态字段；`tenure_zero` 是年限标记，没有新增注册日、流失日或事件序列。 | 输出 25 列白名单阻止随意加入日期；元数据与设计文档保留“静态快照、时间口径不可验证”。真实时序特征只做设计。 |
| C09：不伪造跨表关联 | 当前接口仅接收 Telco 主表；无工单、SaaS 或地区/行业合并。 | 输出字段检查无外部补造列。未来有真实映射仍需另验证客户键、粒度、来源、覆盖率和可用时点后修改合同版本。 |
| C10：版本和训练边界 | 规则保存在 JSON；`TelcoCleaner.fit()` 冻结配置副本，不学习人群统计。数值插补与缩放放入独立 sklearn Pipeline，只允许在训练子集 fit。 | 记录配置、来源哈希、代码版本/指纹、运行时间和输出；验证重复 transform 不继续改变数据，改变留出数据不改变拟合参数。W2 全体中位数 70.35 和临时分箱不被自动带入此接口。 |

本表中的“应保留证据”是交付要求，不代替运行后的实测证明。清洗器负责拒绝输入违约；跨文件哈希、前后对账和诊断表由 W3 运行与验收步骤统一登记。

## 4. 数值和类别的精确含义

### 数值规则

| 字段 | 输出类型 | 合法条件 | 缺失策略 |
|---|---|---|---|
| `SeniorCitizen` | int64 | 只能为 0 或 1 | 拒绝缺失；编码时视为类别 |
| `tenure` | int64 | 大于等于 0，整数，能用 int64 表示 | 拒绝缺失 |
| `MonthlyCharges` | float64 | 有限实数，大于 0 | 拒绝缺失 |
| `TotalCharges` | float64 | 有限实数，大于等于 0 | 主表唯一允许缺失的字段 |

布尔值、复数、正负无穷大、数值解析失败均不作为合法金额。int64 的表示范围是程序存储限制，不是从样本推测的商业上限。

### 类别规则

配置逐字段列出了所有合法值。`gender` 为 Female/Male；Partner、Dependents、PhoneService、PaperlessBilling 为 No/Yes；Contract 为 Month-to-month/One year/Two year；PaymentMethod 为四个原始付款类别。六项互联网服务为 No/Yes/No internet service，多线服务为 No/Yes/No phone service。

自动付款不等于自动续约，电子支票不等于支付失败；清洗不会改变这些字段的业务含义。新批次出现未登记类别时，应先查来源和字段定义、决定是否升版，再重跑。不能让未知类别悄悄变成一排 0。

## 5. 标准化与编码的实施顺序

1. `TelcoCleaner.fit_transform(raw)` 检查合同并生成主表。这一步不使用 y，不从全体客户计算中位数或均值。
2. `split_xy(cleaned)` 划分 X、y 和 ID。22 个 X 字段外的任何字段都会被拒绝；`ColumnTransformer` 前还有 `FeatureContract`，不会靠默认丢弃多余列来掩盖意外带入标签的问题。
3. 先划出示例训练/留出子集，再执行 `build_preprocessor(config)`。默认配置 `seed=42`、`test_size=0.2` 仅服务本周接口演示，不是 W5 冻结的训练/验证/测试方案。
4. 对 X_train 调用 `fit_transform()`：3 个数值字段用训练中位数插补，再用训练均值和总体标准差进行 StandardScaler 标准化；16 个类别字段按预先登记类别独热编码；3 个标记原样通过。
5. X_holdout 只调用 `transform()`，不能重新 fit。若为后续交叉验证，每折都应从一个未拟合 Pipeline 开始，只在该折训练部分拟合。
6. `FiniteArrayGuard` 检查输出为二维有限数值矩阵并维持列宽。名称由 `get_feature_names_out()` 导出，避免只有 x0、x1 而无法追踪来源。

固定类别字典产生 43 个独热列，加 3 个标准化数值和 3 个标记，共 49 列。类别未出现在某次训练划分中仍保留其列，因为字典来自数据合同，不是从留出数据重新发现类别。

若某个训练数值字段整列缺失，`SimpleImputer(strategy='median', keep_empty_features=True)` 保留该列并使用计算用 0 作为回退。这个例外只用于让数值接口可运行，缺失标记仍保留，主表未知金额仍是 NA；绝不能将其解释为该客户真实累计金额为零。此情况必须在运行元数据或检查结果中可见。常量数值列由 StandardScaler 使用安全缩放处理，不人工除以零。

## 6. 可复用性与失败行为

`fit()` 完成后再 `transform()`。清洗器会复制输入，不原地修改传入的 DataFrame；输出字段顺序由配置统一。对自己的 25 列结果再次 transform 应得到相同结果。若已有标记和源字段不一致，程序报错，不能静默覆盖一个被篡改的标记。

核心类可处理满足合同的新批次，不用 7,043 行和历史流失比例作为算法条件。运行入口对当前冻结数据核对来源哈希；配置中的相对数据路径以项目根目录为基准，换输出目录应改配置或使用运行入口支持的参数，不编辑业务函数里的绝对盘符。

异常消息给出字段、规则、数量和少量行位置，便于定位，但不直接打印客户编号。客户级主表、X/y、划分成员和预处理二进制分别保存到已忽略的 `data/processed/`、`models/`；可提交的报告优先保存汇总规则、配置与证据索引。

## 7. 如何理解“清洗后无缺失和异常”

原始 brief 的这句验收要求与 W2 已确认的语义保护原则存在冲突，不能仅靠删掉 11 人或编造金额让字面数字归零。

- 清洗主表：允许 `TotalCharges` 的有据缺失；所有缺失都有标记，其他字段不得缺失。该层不申报“零缺失”。
- 模型接口：训练内插补后须无 NA/无穷大；这是数值接口验收，不是原始信息已经补全。
- 异常检查：只能声明已实施规则未发现未处理违约，不能声称证明现实世界没有任何异常。统计上罕见但符合合同的值继续保留。

W3 完成报告应分别列出主表缺失、模型矩阵缺失、非法值与统计异常处理，并对原始“无缺失”字面要求明确记录这一边界。真实时间计算仍受缺少事件数据约束，详见 [特征工程设计 v1](feature_engineering_design_v1.md)。

## 8. W4 接续检查

W4 从这份可追溯主表出发开发正式候选特征，登记公式、来源、适用人群、缺失含义和泄漏风险。49 列仅是本周基础预处理的展开结果，不能被称为已经完成 W4 的至少 50 项候选特征或特征选择。

后续不能直接把本周示例已拟合预处理器用于一个重新划分的正式评估。应重新建立未拟合 Pipeline，将 W4 特征构建与 W5 训练内插补、编码、缩放一起管理；目标、ID 与标签派生值继续排除。
