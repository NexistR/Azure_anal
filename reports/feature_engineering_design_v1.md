# 特征工程设计文档 v1

日期：2026-09-16。本文件是 W3 的设计交付，依据原始 brief、[八周路线图](roadmap_8w_v1.md)、[W2 清洗交接](w2_to_w3_cleaning_recommendations.md)及 [W3 清洗规则](w3_cleaning_rules.md)。数据是 Telco 公开教学代理快照，不是 Azure 内部客户数据。

本周实现基础清洗、字段合同以及可复用标准化/编码接口。W4 再实现并审查至少 50 项候选特征；W5 才完成正式基线评估。本文件设计 12 项真实时间序列特征，但当前 Telco 无真实事件日期，不能计算它们，更不能用虚构日期凑数量。

## 1. 用普通话解释“特征”

一名客户的一行资料，是机器判断的依据。月费是一个原始特征；“本月用量比上月下降多少”是需要两段真实历史才能算出的特征；“已经流失”是要预测的答案，不能偷偷放进依据里。

特征工程需要同时回答四件事：这个数怎么算、用了哪张表、当时能否知道这些信息、缺信息时怎么办。只增加列数而不回答这四件事，不能形成可信的模型。

## 2. 现有接口与数据结构

| 层次 | 字段构成 | 本周状态与下游用途 |
|---|---|---|

| 清洗主表 | 原 21 列 + churn_label / total_charges_missing / tenure_zero / internet_applicable，共 25 列 | [TelcoCleaner](../src/data/clean.py) 统一类型与类别，保留未知累计金额 |
| 特征输入 X | 3 个数值 + 16 个类别 + 3 个非标签标记，共 22 列 | [split_xy](../src/data/preprocess.py) 严格白名单，客户 ID 和两种标签均不进入 |
| 目标 y、追踪键 | `churn_label`、`customerID` 单独返回 | y 是 Yes→1 / No→0，ID 只负责核对同一客户 |
| 数值矩阵 | 3 个缩放数值 + 43 个独热列 + 3 个原样标记，共 49 列 | 仅为预处理示例；不是已经选择的 49 项独立业务发现，也不是 W4 最终特征集 |

具体字段、顺序和合法类别由 [w3_cleaning.json](../configs/w3_cleaning.json) 定义。清洗主表允许 `TotalCharges` 未知；预处理用训练内插补生成可供算法接收的有限数值。

### 22 个输入字段如何处理

| 组别 | 字段 | 变换与风险 |
|---|---|---|
| 数值 3 项 | tenure、MonthlyCharges、TotalCharges | 训练中位数插补，然后训练均值/标准差缩放；金额只代表快照费用，不是正式 CLV |
| 类别 16 项 | gender、SeniorCitizen、Partner、Dependents、PhoneService、MultipleLines、InternetService、OnlineSecurity、OnlineBackup、DeviceProtection、TechSupport、StreamingTV、StreamingMovies、Contract、PaperlessBilling、PaymentMethod | 逐列固定合法类别独热编码；SeniorCitizen 是 0/1 类别，不当连续年龄；未知类别报错 |
| 标记 3 项 | total_charges_missing、tenure_zero、internet_applicable | 保持 0/1 不缩放；分别表示信息缺口、静态边界、服务适用性 |

所有快照字段的实际采集日均未知，因此不能证明它们严格早于标签确认时刻。本项目只能称为静态快照分类练习；这种整体限制必须随模型报告保留，不能因为排除了 Churn 就声称已经证明没有时点泄漏。

## 3. 拟合与转换的边界

清洗规则本身不学习全样本统计，可以先用于合同检查。插补中位数、均值、标准差等参数则必须先划分数据、只在训练子集 fit，之后留出部分只 transform。类别字典来自已登记的业务合同，使用固定字典并不是观察留出标签。

实际接口是 `build_preprocessor()` 返回未拟合 sklearn Pipeline：`FeatureContract → ColumnTransformer → FiniteArrayGuard`。数值分支为 `SimpleImputer(strategy='median', keep_empty_features=True) → StandardScaler`；类别分支为固定 categories 的 `OneHotEncoder(handle_unknown='error')`；三个标记直通。

本周配置的 `seed=42`、`test_size=0.2` 用于训练/留出接口演示。它不替代 W5 的训练/验证/测试设计，也不产生性能指标。后续换了正式划分就必须重新拟合，不能复用一个见过新测试集的示例预处理器。

训练某个数值列若全部缺失，接口保留该列并使用计算用 0 回退，同时保留缺失标记。这里的 0 不是确认后的历史账单金额；清洗主表仍为未知，不能回写。缺失标记的预测价值以后也要在训练中验证，不默认它必然有效。

## 5. 真实时间特征的统一数据合同

定义 `T` 为每个客户一次评分的真实观察截止时刻。统一使用 UTC 存储，展示时可转换时区；按“天”聚合时需事先约定业务时区。所有历史窗口采用左闭右开 `[T−窗口, T)`，刚好发生在 T 的事件不进入输入。每条事件还需有 `available_at`（系统实际能取得该条记录的时刻），同时满足事件时间和 `available_at ≤ T`，避免把事后补录数据用于过去评分。

公共必需字段为稳定 `customer_id`、快照 `as_of_time=T`，事件表还需唯一 `event_id`、`event_time` 和 `available_at`。先按事件键处理重复和更正版本，不按行号拼接；更正记录也只能使用截至 T 可见的版本。不同表必须有可验证的一致客户键与业务范围。

另需覆盖登记 `coverage_start`、`coverage_end`、采集状态，说明窗口是否完整。完整采集窗口内没有事件，计数可以为 0；采集停止或观测不足，不能把“没数据”当“没行为”。均值、比例和增长率遇到无分母或历史不足时记 NA，加覆盖/适用标记；插补留在训练内。

下表 12 项均是真实历史设计。当前 Telco 只有静态 `tenure` 和费用/订购状态，无这些事件表，因此每项的**设计已交付，实际计算均待真实数据**。不能用本机当前日期减 tenure 生成注册日，也不能把当期月费复制 30 次当作日用量。

## 7. 时间设计如何验收

原始 PDF 提取文本在 [project_brief_extracted.txt](../references/project_brief_extracted.txt) 的第 3 周写的是“设计至少 10 个时间序列特征”。本文件交付 12 项，每项都有公式、窗口、必需真实字段、缺失边界、时点泄漏检查和可计算状态，满足这项**设计数量及内容**要求。

项目介绍的概括表述也提到“构建时间特征”。这部分实际数据计算仍缺前置条件，必须在完成报告中单独披露，不能把设计表当成已经算出 12 列真实结果。补数清单是：真实客户键、评分快照时刻、事件及系统可见时刻、观测覆盖、请求/会话事件、可关联工单及状态历史、合同版本与续约计划。

后续取得真实数据后的最低验证包括：

1. 手工构造跨窗口边界的少量事件，核对等于起点包含、等于 T 排除、迟到入库排除。
2. 同一事件重复或更正时，只使用截至 T 已知的正确版本；覆盖缺失与真实0有不同输出。
3. 追加 T 之后的事件或未来标签，既有 T 特征值不变。
4. 比率分母0、没有历史、新客户、夏令时/跨时区、未结工单、多个合同均有明确行为。
5. 客户键连接进行一对多聚合前先验证粒度；拼接前后快照主键数量不异常增加。
6. 真实日期数据用滚动/时间留出验证；所有训练统计及目标相关编码只在各训练折内拟合。

## 8. W4 候选登记与筛选方案

W4 的每个候选至少登记 `feature_name`、版本、业务解释、类别、源表/源列、精确公式、适用人群、缺失规则、计算可用时点、需 fit 的参数、标签/时点泄漏审查、代码与测试位置。衍生列和独热展开列都要可回溯到这个登记，计数规则提前固定。

在训练内比较至少三类选择方法，例如互信息、L1 正则模型、树模型或 permutation importance。特征选择器不能先看全量 y；交叉验证时要在折内重做选择。相关矩阵/VIF 用于检查冗余，业务上重复的特征需解释取舍。

W3 独热编码保留完整类别列，目的是输出结构稳定，没有声称解决共线性。一个类别的完整独热列之和恒为1，与带截距线性模型会形成冗余；`internet_applicable` 与 InternetService 独热也存在确定关系。W4/W5 应根据模型选择参考类别、合并冗余或正则化，并记录决定，而不是从49列中随意删除一列凑结论。

无真实时间字段时，不能通过这些方法消除所有时点风险；报告继续注明时间可用性无法核实。正式 CLV、毛利、因果收益和 ROI 不由本周费用代理推导。

## 9. 后续使用接口

先按 [清洗规则](w3_cleaning_rules.md)生成主表，再通过 `split_xy()` 取得 X、y、ID。W4 扩展候选时需要同步升级特征白名单、配置验证、字段登记和测试；当前接口会主动拒绝未登记的新列，这是防止标签或随手添加字段混入的约束。

W5 使用当时冻结的训练/验证/测试划分重新建立未拟合预处理器与模型。保存时保存完整 Pipeline 及类别字典、训练参数、数据版本；评分新客户时沿用同一 transform 规则，并监控未知类别、缺失和覆盖变化。本周预处理演示不构成预测性能证明。
