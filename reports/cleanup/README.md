# 工程整理与验证报告

整理日期：2026-10-23。交付对象为独立的 GitHub 工程副本，原项目源码、模型、数据及历史交付记录继续保留。本次仅整理工程、依赖和发布材料，未开展精度调优。

## 保留与精简

运行源码由原来的 55 个 Python 文件收敛为 17 个，覆盖清洗、严格数值解析、历史特征构造、冻结推理、风险分层、SHAP/LIME 和分群分析。推理与风险入口统一为 `scripts/predict.py`、`scripts/score_risk.py`，新增按 SHA-256 恢复本地模型的入口。

| 内容 | 整理方式 |
|---|---|
| 历史训练搜索、模型家族试验、一次性封存与报告脚本 | 从发布副本排除；原项目保留完整研究记录 |
| 本地 Python/Java 环境、下载权重、浏览器 profile、缓存、渲染中间件 | 排除 |
| 原始表、清洗明细、客户分数、含明细的 Notebook/HTML/Power BI | 排除 |
| 冻结推理与分群工件 | 本机可用，Git 和公开 ZIP 均排除 |
| 聚合成果 | 保留 11 个结果文件及阅读说明 |
| 最终论文 | Markdown、Word、PDF 和 3 张图保持原件字节不变 |
| 历史模型性能报告 | 保留数值；改相对归档引用，明确调优已经终止 |
| 依赖 | 分为运行、可选解释、开发三组；统一原验证版本 |

初始盘点约 10.46 GB、11.51 万个文件，主要体积来自环境与缓存；这一规模与发布源码体积属于不同口径。最终发布文件数、字节数和 ZIP 哈希见本目录的机器核验记录。

## 未使用代码审查

原代码中确认的 4 个未使用导入（`load_risk_config`、`dataclass`、`Any`、`pd`）和 2 个未使用绑定（`transform_name`、`train_ids`）位于已排除的研究模块或旧入口。17 个保留模块的 Ruff F、Vulture（置信度至少 80%）与 AST 人工复核均无需要继续删除的项。因此核心源码保持逐字节一致，没有为了缩短代码而改动数值路径。

保留 `_parse_numeric` 的精确整数解析、`TelcoFeatureBuilder`、`FeatureContract`、`FiniteArrayGuard` 的序列化路径，以及 sklearn 协议方法、解释标签和公开分析 API。未被当前 CLI 直接调用不足以证明这些接口无用。旧 SHA 验收脚本依赖原目录和历史文件，未冒充新副本验收依据。

## 验证范围

可移植测试共 25 项：默认 18 项无需模型，另 7 项由 `CHURN_RUNTIME_MODEL` 启用。覆盖严格输入合同、整数精度、风险边界、价值规则、DBSCAN 核心点扩展、冻结模型校验、分块顺序、CLI 输出回滚及禁止覆盖。测试使用人工数据，无训练拟合。

独立本地验证通过：训练与验证共 5,986 行的两类 float32 概率、0.30 决策和 111 列编码矩阵逐值一致；验证集 1,056 行的 13 维分群矩阵、KMeans/DBSCAN 标签与价值规则一致。32 行 SHAP 加性最大误差为 1.605×10⁻⁶，概率重构最大误差为 1.692×10⁻⁷，均满足原冻结容差。全部 26 个 Python 文件编译及 Ruff 检查通过。

历史测试集、客户标识和目标标签未参与等价验证，原源码及工件前后哈希不变。本次验证不产生新的 AUC/F1 结论。详细状态见 [等价验证](equivalence_verification.json) 和 [发布检查](release_verification.json)。

发布材料使用 Git 可跟踪文件清单筛选，并检查相对链接、机器绝对路径、已知客户 ID 模式、部分高置信凭据模式及超大文件。模式检查不代表穷尽所有可能的敏感内容，具体范围在核验 JSON 中记录。GitHub Actions 已配置，尚未在远程仓库运行。
